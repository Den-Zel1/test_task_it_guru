# Inventory Management Service (Test Task)

Микросервис для управления складскими остатками и заказами. Реализован с учетом требований по неограниченной вложенности категорий и аналитической отчетности.

### Настройка окружения
Для работы проекта необходимо создать файл `.env` в корневой папке. 
Пример содержимого (совместим с текущим docker-compose.yaml):

```env
# Параметры PostgreSQL
POSTGRES_USER= your_user
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=it_guru_test_db
POSTGRES_HOST=db
POSTGRES_PORT=5432

##  Стек технологий
- **Backend:** Python 3.12.13 + FastAPI
- **DB:** PostgreSQL 15 + SQLAlchemy 2.0
- **DevOps:** Docker (на базе Debian Bookworm), Docker Compose
- **Package Manager:** uv (использован для сборки и локальной разработки)

 Тестирование
В проект включены функциональные тесты на базе pytest. Они проверяют создание заказа, увеличение количества товара и контроль остатков на складе.

bash
docker exec -it fastapi_service pytest test_main.py


Анализ и оптимизация (п. 2.3.2)
При росте нагрузки (от тысячи заказов в день) предложены следующие меры:
Оптимизация дерева категорий: Текущая модель Adjacency List требует рекурсивных CTE-запросов для поиска корня. Для ускорения отчетов рекомендуется денормализация: добавить в таблицу products колонку root_category_id.
Индексация:
idx_orders_created: ускоряет выборку за "последний месяц".
idx_order_items_product: ускоряет агрегацию проданных штук.
Materialized Views: Отчет "Топ-5" вынесен в SQL View. При росте данных его следует заменить на MATERIALIZED VIEW с обновлением по расписанию, чтобы исключить расчет рекурсии "на лету".

Структура проекта
main.py — Точки входа API, логирование (logging) и бизнес-логика.
models.py — Описание реляционных моделей (SQLAlchemy).
database.py — Инициализация подключения к БД и сборка DATABASE_URL через python-dotenv.
init.sql — Схема БД, тестовые данные и SQL View для отчетов.
test_main.py — Набор тестов для проверки логики заказа.
.env — Конфигурация окружения (вынесена из кода).
Особенности реализации
Логирование: Реализовано через стандартный модуль logging, логи выводятся в stdout контейнера. Настроена ротация логов в Docker (max-size: 10MB).
Надежность: Контейнер приложения использует healthcheck, ожидая полной готовности PostgreSQL перед запуском сервера.
История цен: Цена фиксируется в order_items в момент покупки, что гарантирует неизменность суммы заказа при изменении цен в будущем.
